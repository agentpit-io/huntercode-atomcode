# 来源说明 · 一次性导入

> 本仓库是 **HunterCode 投研终端的 AtomCode 国内发行版**。
> Web / API / SKILL / MCP 的代码**一次性导入**自 HunterCode 社区版，之后本仓库独立演进。

## 1. 不同步声明

按 2026-09-22 的已拍板决策 2：

- **不做持续同步**。本仓库导入之后就是独立代码库，不写同步脚本、不建 lock 同步机制、
  不用 git submodule、不设 `vendor/` 只读区。
- 上游有需要的改动时**人工单独同步**，同步时在本文件追加一条记录。
- 因此：**本仓库里的文件可以直接改**，不存在"改了会被同步覆盖"的问题。

（这一条推翻了开发计划 v0.2 第 4.1 节的"快照 + lock + `vendor/` 禁止手改"方案。
计划文档原样保留在 `docs/design/`，以本文件为准。）

### 4.1 两个必须在 M1 处理的问题

1. **工具名前缀不一样**。SKILL 里写的是 opencode 风格的 `<服务名>_<工具名>`
   （`uzi_stock_deep_analysis`、`watchlist_stock_news`、`portfolio_update_risk_profile`），
   AtomCode 的 MCP 工具名是 `mcp__<服务名>__<工具名>`
   （实测：`mcp__akshare__akshare_call`）。`needs_tools` → `allowed-tools` 的转换要做名字映射。
2. **用户身份注入没有对应机制**。6 个 hunter 系 MCP 都从工具参数里取 `_hermes_user_id`，
   这个字段由 opencode 插件 `hunter-mcp-context.ts` 在 `tool.execute.before` 注入。
   AtomCode 没有能改 MCP 工具参数的插件点——但 **PreToolUse hook 可以改参数**
   （`hookSpecificOutput.updatedInput`，已确认源码支持），或者在 `.mcp.json` 里给每个
   server 配 `env: {"HUNTER_USER_ID": "..."}`（MCP 代码里有这个兜底分支）。
   私有化单机场景下后者更简单（一个工作区一个用户）。M2 定夺。
