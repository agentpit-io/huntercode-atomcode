## 0. 一页结论

1. **可行，且比 v0.1 估计的更省力的部分有两块，更难的部分有一块。**
   - 更省力：AtomCode 的技能格式（`SKILL.md` + `name/description` 头部）和我们现有 SKILL **几乎同构**，转换从"写转换器"降为"复制 + 小改占位符"；MCP 的 stdio 传输原生支持，而我们的 MCP 恰好全是 stdio。
   - 更难：v0.1 以为能"用配置整体替换系统提示"或"关掉意图分类/自动编译"，**实测均不成立**——编码人设在 `atomcode-coding/src/persona.rs`（约 690 行），只能追加指令、不能替换，且没有配置开关。领域改造风险从"中"上调为"中高"。
2. **v0.1 有 13 处上游事实错误、5 处本地资产事实错误**（见第 2 节），任务包需要重写，不能直接拿去执行。
3. **总工作量重估：18–26 个 AI 辅助人日**（v0.1 为 25–35）。节奏仍按 3 周 + 1 周缓冲。
4. **独立仓库带来的新问题**：v0.1 假设发行版放在 hunter-community 的 `distros/atomcode/` 下；现改为 GitCode 独立仓，需要设计"从 hunter-community 同步 SKILL / MCP / Web 的方式"（第 4 节）。
5. **开工前需要你拍板 4 件事**（第 9 节）。

## 2. v0.1 方案差异修正表

### 2.1 上游 AtomCode（13 处）

| # | v0.1 假设 | 实测 | 影响 |
|---|---|---|---|
| 1 | 4 个 crate：core / tuix / cli / daemon | **14 个 crate**，无 `atomcode-core`；核心分布在 kernel / coding / capabilities / config | 任务包里的源码路径全部要改 |
| 2 | daemon 需 `ATOMCODE_INCLUDE_DAEMON=1` 单独构建 | 那只是打包开关；**`atomcode daemon` / `atomcode webui` 是 CLI 子命令**，官方二进制即可 | 不必自己编译 Rust，直接用官方 release |
| 3 | 默认 127.0.0.1:13456 | 成立；webui 用 13457；支持 `--host --port --no-auth` | — |
| 4 | 端点 /chat /sessions /config /auth /models /mcp /skills | 远多于此：`/chat/{stop,active,permission,user-input}`、整组 `/live/*`、`/projects /cd /project`、`/providers*`、`/fs/*`、`/health`、`/shutdown` 等；**MCP 只有 `/mcp/status` `/mcp/reload`** | 适配层工作量需按真实接口重估 |
| 5 | 权限模式 BypassAll | 四档：`build`（默认）/ `accept_edits` / `plan` / `bypass`；/chat 可按请求带 `approval_mode` | **`plan` 档可能天然只读，可作"研究模式"**，TP-01 需验证 |
| 6 | SSE 事件格式未知 | 已知：runtime_info、session_assigned、text、reasoning、tool_batch、tool_start、tool_output、tool_progress、tool_result、tokens、**artifact_start/content/end**、permission_request、user_input_request、policy_intervention、done | 自带 artifact 事件，Kronos 图表可走原生通道 |
| 7 | 单用户、单工作目录 | **支持多会话、多工作目录**（请求带 `working_dir` + `session_id`，MCP 按目录缓存） | 多租户 Demo 站难度下降，但仍无用户身份 |
| 8 | MCP 支持 HTTP 与 stdio | stdio + Streamable HTTP；**无旧式 SSE 传输**；项目 `.mcp.json` + 用户级 `~/.atomcode/mcp.json` | 我们全是 stdio，无障碍 |
| 9 | Skill 在 `.atomcode/skills/*.md` | 项目与用户各 5 个目录（含 `.claude/skills`、`.agents/skills`、`.atomcode/skills`）；**目录式 `<名>/SKILL.md`**；头部 name / description / allowed-tools / user-invocable；占位符 `$ARGUMENTS`、`$N` | 与我们格式同构，转换成本大降 |
| 10 | Hook 13 个扩展点，shell + webhook，hooks.toml | **实际生效 8 个事件**（PreToolUse / PostToolUse / PostToolUseFailure / SessionStart / SessionEnd / UserPromptSubmit / Stop / StopFailure）；配置 `.hooks.json`；**只有 shell**，webhook 属旧引擎已不触发；Pre 可 deny 或改参数；`atomcode hooks test` 存在 | 审计/预算不能直接走 webhook，改为 shell 脚本内自行 curl |
| 11 | `.atomcode.md` 可能覆盖系统提示；DEFAULT_SYSTEM_PROMPT 可替换 | `DEFAULT_SYSTEM_PROMPT` 已删；人设在 `atomcode-coding/src/persona.rs` 约 690 行；项目指令（`.atomcode.md` / ATOMCODE.md / AGENTS.md / CLAUDE.md 取其一）**只能追加**，人设里有"项目指令优先"声明；配置里的 `system_prompt` 字段未被读取 | **领域改造核心风险**，见第 5 节 |
| 12 | task_classifier / auto_compile / auto_diagnose / project_context | **这 4 个模块不存在**；对应物是 `discipline/verify.rs`（改代码后提醒校验，可用 `ATOMCODE_VERIFY` 关）、`skill_first.rs`（仅 DeepSeek/Qwen）、`session/context.rs`（注入环境+git 状态）；开关只有环境变量 | 编码倾向比预想的"软"，但人设本身是硬的 |
| 13 | tag 形如 release/vX.Y.Z；Rust 版本未知 | tag 为"快速发布-atomcode-release-时间戳"；**版本号看 `latest.json`（v5.1.0，6 个平台二进制 + sha256）**；另有 npm `@atomgit.com/atomcode`、brew；Rust 1.88+；`docker/` 有 Dockerfile-Daemon 但依赖本地 dist | pins.lock 记"版本号 + 平台 sha256"而非 tag |

附：内置工具 `edit_file / write_file / search_replace / bash / read_file / grep / glob / web_search / web_fetch / use_skill` 均存在；**`auto_fix` 不存在**；另有 `parallel_edit_files`、`ast_grep`、`bash_start/poll/kill`、`task`、`todowrite`、`memory`、`lsp`、`atomgit_*` 等需要纳入白名单审视。上游**没有**任何"领域定制 / 垂直发行版"官方机制。

## 4. 独立仓库设计

### 4.1 与 hunter-community 的关系：单源、快照同步

hunter-community 仍是 SKILL / MCP / Web 的**唯一真源**；huntercode-atomcode 只存"AtomCode 发行版特有的东西"，其余通过**锁定提交的快照同步**引入：

- 不用 git submodule：GitCode 用户拉 GitHub 子模块在国内不稳定，且子模块对非开发者不友好。
- 用 `tools/sync_community.sh`：按 `community.lock` 里的 hunter-community 提交号，把指定目录复制到 `vendor/`，生成差异报告；产物入库（保证 GitCode 单仓可独立构建、可追溯）。
- 真正需要改 SKILL / MCP 的地方，**先改 hunter-community 再同步**，禁止在 `vendor/` 手改（CI 校验 vendor 与 lock 一致）。

### 4.2 目录结构（草案）

## 5. 领域改造（核心风险）

### 5.1 手里有的杠杆（全部不改内核）

| 层 | 手段 | 预期效果 |
|---|---|---|
| 指令 | `.atomcode.md` 写投研人设；借用人设中"项目指令优先"声明覆盖编码规则 | 主力手段，效果待测 |
| 权限档 | 研究会话用 `plan` 或 `build`，禁写类工具由 hook 拒绝 | 若 `plan` 只读且不影响 bash/MCP，则是最省事的方案 |
| hook | PreToolUse 拒绝 edit_file / write_file / search_replace / parallel_edit_files 等；bash 危险命令二次拦截；UserPromptSubmit 注入当日行情摘要、持仓约束 | 硬约束，确定有效 |
| 环境变量 | `ATOMCODE_VERIFY=off`、按需关 TODO / SUBAGENT / MEMORY_TOOL | 去掉"改完代码要校验"类提醒 |
| 工作区 | 研究资产目录结构；无 git 或最小 git，减少 git 状态注入 | 降低编码语境 |
| 技能 | 技能头部 `allowed-tools` 限定工具 | 单技能内收窄 |

### 5.2 决策点（第 1 周末）

- 评测：5 类问题（单股基本面、持仓论点复核、因子查询与回测、Kronos 预测、一手情报汇总）× 3 次，AtomCode 版 vs 现有 opencode 版。
- 打分：准确性、工具调用正确率、输出规范符合度、步数与耗时。
- **≥ 80%：不 fork。< 80%：进入最小补丁**，补丁范围改为：
  1. `persona.rs` 支持通过配置指定外部人设文件整体替换（未配置时行为不变）；
  2. 让 model 配置里现有的 `system_prompt` 字段真正生效（这更像上游遗留缺陷，提 PR 成功率较高）。
- 补丁以 PR 提回上游；我们在 GitCode 上 fork 到 agentpit-io，pins.lock 记录 fork 提交与对应上游版本。此时需要自行构建二进制（Rust 1.88+，本地 Mac 构建，**禁止在 agentpit 服务器上编译**）。
