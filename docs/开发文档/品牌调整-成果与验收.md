## 1. 改了什么

### 1.1 模型选择器显示真实模型名

改之前：输入框右下角与下拉项都是 `hunter-chat（全局生效）`，分组标题是 provider id `ONEAPI`。
改之后：`Gemini 3.8 Flash（全局生效）`，分组标题 `Google Gemini`。

**真实模型是实测出来的，不是照抄文档**（2026-09-22 19:51，从香港调官方网关）：

| 探针 | 结果 |
|---|---|
| `POST /chat/completions` 的响应 `model` 字段 | `hunter-chat` —— **回显的是别名，从这里看不出真实模型** |
| `GET /api/saas/llm/v1/models` | `hunter-chat` → `display_name: "Gemini 3.8 Flash"`；`hunter-deep` → `"Gemini 3.1 Pro"` |
| 让 `hunter-chat` 自报模型标识 | `gemini-3.8-flash` |

后两条互相印证，所以显示名按 **Gemini 3.8 Flash** 写。

做法（`apps/web/app/lib/atomcode/labels.ts` + `index.ts` 的 `providersView`）：

- 新增两个环境变量 `HCA_LLM_MODEL_LABEL` / `HCA_LLM_PROVIDER_LABEL`，web 容器运行时读。
- **请求用的模型 ID 一个字没改**：返回体里 `id` 仍是 `hunter-chat`，只改了给人看的 `name`；
  前端 `resolveModelKey` 比的是 id，会话里存的 `provider/model` 键也不受影响。
- 两种写法：整串当一个名字（只在该通道只有一个模型时生效）、或 `id=名字,id=名字`。
- **不配置就显示原始 ID**。代码里没有任何内置猜测 —— 自建 OneAPI 的 `hunter-chat` 背后
  可能是别的模型，写死一个名字就是红线 1 说的"冒充"。
- `install.sh` 按通道给默认值：oneapi **且网关地址就是官方那个**才填 Gemini 名字（自建 OneAPI 留空）；
  official / ollama 用用户自己填的模型名，分组标题分别是「自带官方 Key」「本地 Ollama」。
  另加 `--model-label` / `--provider-label` 两个参数。
- 前端只动了一行样式：分组标题原来是 `textTransform:'uppercase'`，会把「Google Gemini」喊成
  「GOOGLE GEMINI」，去掉。
