## 2. 设计落地时的三处修正

设计文档是开工时写的，落地与实测推翻/补充了三条，文档已同步更新。

### 2.1 Kronos 图「当场有、刷新就没」—— 开源迁移里少一张表

设计 §4.1 说「Kronos 完全不经过 agent，换底座后原样可用」。**前半句对，后半句不完整**。

Playwright 的「刷新后会话恢复」第一次真跑时露了馅：Kronos 图在当前页面上好好的，刷新之后消息流里没有了。查下去是 api 侧的事，与 agent 底座无关：

```
api 日志：[chat_kpred] 拉 session 报告失败: relation "chat_kpred.reports" does not exist
接口返回：{"items":[],"count":0}   ← 200，不是错误
```

`apps/api/app/routers/chat_kpred.py` 从一开始就往 `chat_kpred.reports` 写报告、并用它做刷新恢复，**但 `db/migrations/` 的 0001–0022 里没有建这张表的迁移**（逐个查过）。写入与读取都包在 `try/except` 里，所以不报错、只降级 —— 接口照样 200，用户只看到「图没了」。

修法（不改 api 源码）：

- 新增 `db/migrations/0023_chat_kpred_reports.sql`，按 `chat_kpred.py` 的 `INSERT` / `SELECT` 逐列对出 DDL，全部 `IF NOT EXISTS`；
- compose 里给 api 加 `HUNTER_MIGRATIONS_DIR=/opt/hca-migrations` 并把仓库的 `db/migrations` 只读挂进去。

挂载前先核过一遍：**仓库的 0001–0022 与镜像 `/opt/hunter-migrations` 里的 24 个文件逐字节一致**（`sha256sum` 逐文件比对，`diff` 无输出），所以挂载不会改变已有迁移的行为，只是多一个 0023。

实测：

```
迁移 | 迁移目录：/opt/hca-migrations
迁移 | ② 增量迁移：共 24 个迁移文件，已应用 23 个，本次待执行 1 个
迁移 |   [1/1] 0023_chat_kpred_reports.sql 完成，耗时 0.067 秒
postgres | select to_regclass('chat_kpred.reports') → chat_kpred.reports
```
补完之后「刷新后会话恢复」这一步稳定通过（§4.2 第 8 步）。

### 2.2 `permission_request` 本轮一次都没触发 —— 所以只能靠单测钉住

设计 §8.2 定的是「自动 deny + 在消息流里画一张 error 状态的工具卡」。10 步端到端跑完，**`permission_request` 一次都没出现**（`.mcp.json` 的 `autoApprove` + `guard.py` 的硬约束把它压成了残余情形，与 M1/M2 的观察一致）。

不能因为「没触发」就说它对。把决策逻辑从 `live-hub.ts` 里抽成纯函数 `permissionDenyPlan()`，用 4 条单测钉住：一律回 `deny`、带上 `tool_name`、用户看得见「哪个工具被拒了、为什么」、**回 daemon 失败要如实写进提示而不是假装拒绝成功了**。

`user_input_request`（本发行版用 `ATOMCODE_REQUEST_USER_INPUT=0` 关掉了）与 `policy_intervention` 同样没触发，如实记为**未在真实链路上验证**。

### 2.3 富卡片没有「在右侧查看」入口 —— 工具进 ArtifactPanel 走的是通用卡片

设计 §4.1 第三行说「点卡片 → `onOpenArtifact(part)` → ArtifactPanel 看原始 JSON」。实测**只有通用卡片（`ToolCallCard` 的 fallback）有这个入口**，而且要 `output` 超过 200 字符才出按钮；7 张富卡片（`StockQuickviewCard` 等）没有展开态、也没有这个按钮。

这不是适配层的问题（前端本来就这样），但验收用例得照实分成两步：第 4 步验富卡片，第 5 步专门问一个只会走通用卡片的工具（akshare）来验 ArtifactPanel 的工具模式。

### 3.2 本轮在真实部署上抓到并修掉的 5 个缺陷

这一节全部是「代码写完之后、在测试机上真跑才发现」的，每条都附实测证据。

**① web 读不到 daemon token，整个适配层是废的 —— 而容器 healthy**

```
docker logs hca-web：
[atomcode] 读不到 daemon token： /run/hca/daemon-token EACCES: permission denied
```
token 由 daemon 的 entrypoint 生成，`0640 hca:hca`（uid/gid 10001），而 web 镜像跑的是 `nextjs`（uid 1001 / gid 65533）。web 的健康检查只看首页，**首页照样 200，容器一直是 healthy**，`docker compose ps` 六个绿。

- 修：compose 给 web 加 `group_add: ["10001"]` —— token 保持 0640 不放宽，web 拿到读权限。
- 更重要的修：`up.sh` 的自检本来就有「web→daemon」一跳，但它当时打的是 `model=—` 然后**照常报「完成」**。改成 `web→daemon` 或 web 首页任一失败即 `die`，部署直接算失败。

**② 管理员账号从来没建成，而 `admin.txt` 里躺着一个口令**

```
[admin] ✗ 注册失败 HTTP 422：value is not a valid email address:
        The part after the @-sign is a special-use or reserved name … 'admin@hca.local'
```
`.local` 是 RFC 6761/6762 的 special-use 域名，api 的 `email_validator` 直接拒（`.localhost` / `.example` / `.test` / `.invalid` 同理）。更糟的是 `create_admin.py` **先写 `admin.txt` 再注册**，注册失败文件却留下了 —— 一份「口令对应一个不存在的账号」的记录，比没有文件更坏。而 `up.sh` 当时只打一个 ⚠ 就继续，最后报「完成」。

- 默认邮箱改 `admin@hca.agentpit.io`（自有域名子域）；
- `admin.txt` **只在账号真建出来之后才写**，建完立刻用它登一次做回验；
- `up.sh` 里管理员建不成 = 部署失败（web 对公网 + 免登录已关，没账号这套栈没法用）。

**③ 幂等判据用错了 HTTP 码，第二次部署报假失败**

第二次 `up.sh` 打出 `[admin] ✗ 注册失败 HTTP 400：{'detail': '此实例需要邀请码'}`。原来的代码用「register 返回 409」判断账号已存在，但 `REGISTRATION_MODE=invite` 下**邀请码校验排在查重之前**，已存在的邮箱再注册返回的是 400，从 400 里分不出「已经有这个人了」还是「真要邀请码」。改成**先拿 `admin.txt` 里的口令登一次**，登得上就算幂等通过，登不上才去注册。

**④ `chat_kpred.reports` 表缺失** —— 见 §2.1。

**⑤ 模型绕过 MCP 层直接跑 MCP server 的源码（P1-18 的具体形态，这次被拍到了）**

第 4 步「问一个会调 MCP 的问题」有一次没出富卡片。那次的失败截图留在 [`docs/evidence/M3/绕过MCP层-bash直跑server源码.png`](../evidence/M3/绕过MCP层-bash直跑server源码.png)（`docs/screenshots/M3/` 下是修好之后那次通过的留档），上面模型干了这么一串：

```
grep {"path":".eval","pattern":"stock_quickview"}
read_file {"file_path":"/opt/hca/mcp/watchlist_mcp.py"}        ← 被 guard 拒了
bash {"command":"/opt/hca/venv-hunter/bin/python -c \"import sy…"}  ← 放行了
bash {"command":"python3 -c \"import asyncio, sys\nsys.path.ins…"}  ← 放行了
→ 结论：…现价 1252.57 元…（数据来源: stock_quickview）
```
数字是真的，但**没走 MCP 层**：拿不到 `_hermes_user_id` 注入（多用户下会取错人的账本）、不进 MCP 审计、前端收到的工具名是 `bash` 而不是 `watchlist_stock_quickview`，**富卡片直接退化成通用卡**。

为什么 guard 没拦住：`check_bash` 只检查**首词之后**的 token 是否越界，而 `/opt/hca/venv-hunter/bin/python` 正是首词（basename 归一成 `python`，在白名单里）；`sys.path.insert(0, '/opt/hca/mcp')` 又藏在引号里，压根不是一个独立 token。

修：`guard.py` 加一条对**整条命令原文**的规则 —— 出现 `/opt/hca` 一律 deny，理由里说清「那是本发行版自己的实现目录，不是数据；要哪份数据就调对应的 MCP 工具」。补 3 条单测（首词形态、内联脚本形态、以及「别把正常的 `python3 -c` 只读计算一起拦了」）。改完之后同一用例连跑两轮都稳定出富卡片。

> 这条同时把待办池 **P1-18 从「要定的事」变成「已决定并已实现」**：硬约束靠 hook，不靠人设。

**另外**：`tools/eval/sync-to-test.sh` 的 `rsync --delete` 会把测试机上的 `deploy/secrets` 删掉（开发机没有这个目录，它在 `.gitignore` 里）。已加 `--exclude 'deploy/secrets'`，注释里写明原因。

```
                             "message.part.delta":12,"session.updated":1,"message.updated":1}
conn2 收到本轮终态     是
空窗期事件有没有补发    没有（即发即弃，重连前的事件不补）
刷新（GET /message）    1 条 assistant 消息，1895 字符
```
结论三条：重连后的连接**能继续收到同一轮的事件**；**空窗期的事件不补发**（LiveHub 没有回放缓冲，是即发即弃）；但刷新走 `GET /session/{id}/message` 能把这一轮**完整**拿回来，所以空窗造成的洞是可恢复的。这条限制已写进设计文档 §9 与待办池（P2）。

### 4.4 这一轮里，测试脚本自己错了三次（如实记录）

验收脚本不是一次写对的，三处断言写松了会把「没做到」判成「过」。都已改正，改正的理由写在脚本注释里：

1. **第 4 步**原来断言 `/stock_quickview|贵州茅台/`。可这四个字**在用户自己发的那句话里就有**，工具压根没调也会命中 —— 正是 §3.2 ⑤ 那次绕过 MCP 的运行，旧断言判它「过」。改成只认富卡片自己才画得出的三个标志。
2. **第 6 步**原来断言 `/risk_profile|风险|保守/`，「风险 / 保守」同样出自用户输入。改成只认 `risk_profile` / `use_skill` 这类不可能出自用户输入的串；同时把触发方式从「自己打一句像技能的话」改成**走能力库入口**（实测同一句话模型有时调 `use_skill`、有时不调，靠运气的用例不该进验收）。
3. **第 5 步**原来是「点一下富卡片就算过」。前后两张截图**逐字节相同**（`md5sum` 一致）—— 富卡片根本没有展开态，那个 ✅ 是假的。重写成通用卡片 + 「在右侧查看」，见 §2.3。

另有一处小的：SSE 脚本最初把两条连接都会收到的 `server.connected` 当成「疑似有补发」，已排除后重测。

## 8. 交接给下一个里程碑

1. **部署形态已成型**：`bash deploy/up.sh` 一条命令从零拉起六个服务并自检，自检不过即失败退出。回归测试可以直接拿它当前置条件。
2. **两套端到端脚本可复用**：`tools/e2e/m3-web.mjs`（支持 `--only <用例名,…>` 只跑某几步）与 `tools/e2e/m3-sse-reconnect.mjs`。跑之前要在测试机 `~/hca/pw` 装过 playwright + chromium（已装）；脚本要从 `~/hca/pw` 目录跑（`node_modules` 在那儿）。
3. **验收断言的教训**：§4.4 那三处都是「断言命中的是用户输入里本来就有的词」。写新用例时，断言只认**被测系统产出的东西**，不认用户输进去的东西。
4. **`db/migrations` 现在是 api 的迁移源**（compose 里 `HUNTER_MIGRATIONS_DIR`）。以后再发现 api 缺表，加一个 `00XX_*.sql` 即可，但**不要改 0001–0022** —— 它们与上游镜像逐字节一致是这套挂法成立的前提。
5. **底座没有 fork**，仍是官方 5.1.0（`sha256 40d86fa3…`），M2 的结论未被本轮推翻。
