M5 复核：m3-web.mjs 第 07 步「Kronos 预测图进 ArtifactPanel」的断言认了用户输入
时间：2026-09-22 16:2x（上海）

== 1. 旧断言 ==
  await box().fill('预测 600519 未来 5 天走势')
  ...
  if (!/600519|贵州茅台/.test(inner)) throw new Error('ArtifactPanel 的 iframe 里没有 Kronos 报告内容')

`600519` **就在用户刚输进去的那句话里**。只要 iframe 里回显了股票代码就算过 ——
报错页、占位页、「600519 预测失败」都能过。这与 tools/e2e/README.md 里记的
M3 那三处是同一个错（那条规矩就写在同一个文件里，而这一处漏掉了）。

== 2. 新断言 ==
认这份报告**特有的结构**（这些词一个都不在用户输入里）+ 一张真有数据的表：
  · 结构标志 ≥4/6：综合评分 / 因子明细 / 每日预测 / 置信度 / 预测涨跌幅 / Kronos
  · 「每日预测」表 ≥3 行：/20\d\d-\d\d-\d\d[\s\S]{0,80}?\d+\.\d\d/

== 3. 用部署中那份**真报告**验证（不是造的样例）==
取自测试机 hca-postgres 的 chat_kpred.reports（最近一条，600519 贵州茅台，
composite_score=29，rating=偏多，content_html 26 775 字节，生成于 2026-09-22 13:19 CST）。
去掉 script/style 与标签后 2 434 字，正文里确实有：

  当前 ¥1252.94 · 5日后预测 ¥1289.95 +2.95% · 置信度 62% · 信号分歧 中
  综合评分 +29/100（8 因子加权 · 40% Kronos + 60% 因子）
  因子明细：主力净流入 +0.29/35%、Kronos技术 +1.00/10%、筹码分布 +0.60/15% …
  每日预测：2026-09-23 … 2026-09-29 共 5 行开/高/低/收

判定结果（node 跑新判据）：
  过   真报告（该过）                      标志=6/6  行=6
  拒   错误页里带 600519（该拒）            标志=0/6  行=0     ← 旧断言会判「过」
  拒   只有用户原话（该拒）                 标志=0/6  行=0     ← 旧断言会判「过」
  拒   有标志但没数据行（该拒）              标志=5/6  行=0
0 条不符合预期。

== 4. 顺带记一个事实 ==
这套部署里 Kronos **是真的在出数**（上面那两条报告是 M3/M4 真跑出来的，
不是占位）。M4 报告里「kronos 没 key、期望内报错」说的是 **MCP 那条路径**
（`kronos_health` / `kronos_predict` 两个工具没配 KRONOS_API_KEY），
和网页上的 kpred 走的不是同一条链路（kpred 走 hermes-api 的 Kronos，不经 agent）。
两件事不要混为一谈 —— 这一点写进 M5 报告的遗留问题里。

== 5. 同一轮在 m4-regression.mjs R3 上查出的第 5 处：判据**压根没有断言** ==

旧代码（R3「对话式投研」的第 ② 条「全中文」）：

    const en = body.match(/\b[A-Za-z]{3,}(?:\s+[A-Za-z]{3,}){4,}/g) || []
    const enBad = en.filter((s) => !/PE|ROE|TTM|.../i.test(s))
    // ③ 不给买卖指令
    const advice = body.match(...) || []
    if (advice.length) throw new Error(...)          ← ③ 有 throw
    return `... 英文散句 ${enBad.length} 段 ...`      ← ② 只写进返回串，**没有 throw**

② 无论多少段英文都算"过"。而且判的是整页 `innerText`，里面混着
用户自己发的那句、工具卡片里 akshare 返回的英文列名、界面自己的英文标签
—— 既会误伤也会漏判。

新代码：从后端 `/api/opencode/session/{id}/message` 原样取回这一轮
`role=assistant` 的 text part（刷新时前端调的同一个端点，且 BFF 在这一跳
会用 cachedFix 回放出口守卫的修正），只判这段正文，**并且真的 throw**。

判据验证（node 直接跑，四个样本）：
  过  浸泡里真实的中文回答（该过）                    英文散句=0
  过  中文夹金融缩写 PE/TTM/ROE/EPS/MACD（该过）       英文散句=0
  拒  整段英文（该拒）                               英文散句=1
  拒  中文里夹一段英文散文（该拒）                     英文散句=1
0 条不符合预期。

注：这条改完之后，R3 会在「模型真说英文了」时**失败**。如果今晚回归时它红了，
那是守卫没生效的真结论，不是脚本坏了 —— 原样记进报告。
