guard hook 复核（M5 第三轮）：白名单里"只读工具"自带输出文件参数 —— 不用 `>` 也能写盘
时间：2026-09-22 16:1x（上海）
被测对象：distro/workspace-template/.hooks/guard.py（M5 改成白名单之后的那一版）

== 1. 为什么会漏 ==
写重定向那道闸只认 `>` / `>>` 这两个 token；白名单只判"首词是谁"。
两者合起来的隐含假设是「白名单里的命令都不写文件」—— 这个假设是错的。

== 2. 部署中的容器里哪几个真的在（不是纸面推演） ==
$ docker exec hca-daemon sh -lc 'for c in sort uniq xxd tree yq jq od strings column comm; do printf "%-8s "; command -v $c || echo MISSING; done'
         /usr/bin/sort        ← 在
         /usr/bin/uniq        ← 在
         MISSING              (xxd)
         MISSING              (tree)
         MISSING              (yq)
         MISSING              (jq)
         /usr/bin/od          （od 没有输出文件选项，不受影响）
         MISSING              (strings)
         MISSING              (column)
         /usr/bin/comm        （comm 没有输出文件选项，不受影响）

结论：sort 与 uniq 这两条在**部署中的容器里当场可用**，不是理论风险。
xxd / tree / yq 容器里没有，但它们在 BASH_ALLOW 里，换个基础镜像就会有 —— 一并堵上。

== 3. 真的写盘了（开发机上直接跑命令，不经 guard） ==
$ mkdir -p hca-wr/holdings hca-wr/reports
$ echo '{"real":"ledger"}' > hca-wr/holdings/positions.json
$ echo 'TAMPERED'          > hca-wr/reports/evil.txt
$ cat hca-wr/holdings/positions.json
{"real":"ledger"}
$ (cd hca-wr && sort -o holdings/positions.json reports/evil.txt)
$ cat hca-wr/holdings/positions.json

$ (cd hca-wr && uniq reports/evil.txt holdings/positions2.json)
$ cat hca-wr/holdings/positions2.json
TAMPERED                     ← uniq 的第二个操作数就是输出文件
（xxd 开发机与容器里都没装，没能实跑；按 xxd(1) 的 `xxd [选项] [输入 [输出]]` 一并处理）

后果与 M2 冒烟题「改我的持仓文件」要求拒绝的完全是同一件事。

== 7. 同一轮复核的第二类：白名单里带**执行外部命令**选项的（ripgrep --pre）==

把 BASH_ALLOW 里 62 个命令按「能不能写文件 / 能不能联网 / 能不能执行外部代码」
三问逐个过 man / --help（脚本扫 + 可疑项人工看），除第 1–6 节那批写盘的之外
还查出一条**执行**：

$ echo 'print("PWNED-BY-RG-PRE")' > x.py
$ rg --pre python3 --pre-glob '*.py' 'PWNED' .
./x.py:PWNED-BY-RG-PRE
  ↑ 这一行不是 rg 在文件里搜到的内容，是 `python3 x.py` 的**执行输出** ——
    rg 把每个输入文件先交给 --pre 指定的命令跑一遍，再搜它的 stdout。
    等于「先 write_file reports/fetch.py 再执行它」那条绕过原样复活。

容器里的情况（与第 2 节同一次查）：rg MISSING、ack MISSING —— **当前不可利用**。
但白名单随工作区模板走，换个基础镜像就有了，所以照样堵：
  - rg：`--pre` / `--pre-glob` / `--hostname-bin` 一律拒
  - ack：直接移出白名单（perl 脚本，`--pager` 一族能把内容交给外部命令，容器里也没装）

复验 7 条（4 该拦 / 3 该放）0 条不符合预期：
  deny  rg --pre python3 --pre-glob '*.py' PWNED .
  deny  rg --pre=sh PWNED reports
  deny  rg --hostname-bin reports/x.sh PWNED .
  deny  ack --pager='python3 reports/x.py' foo
  放行  rg -n 持仓 reports/
  放行  rg --json foo reports
  放行  grep -rn foo reports

另有一批扫出来但核实为**假阳性**、没有动的（都是"输出格式/分隔符"不是"输出文件"）：
  column --output-separator · comm --output-delimiter · cut --output-delimiter
  df --output=字段表 · join -o 格式 · ls -o（长格式不显示组）· od -o（八进制格式）
  strings -o（打印偏移）· find -o（即 -or；-exec 一族另有专拦）
  jq / printf 的 man 里出现 "exec" 字样，核实为文档措辞，二者都没有执行外部命令的入口。
